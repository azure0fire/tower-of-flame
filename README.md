# 불꽃의 탑 - MVP 프로토타입

현재 구현된 범위: 캐릭터 선택 → 탑 진입(항상 1층부터) → 턴제 전투(공격/방어/스킬1/스킬2) → 승리 시 다음 층, 패배 시 재도전.
가방/대장간/상점/설정 탭은 아직 자리만 잡아둔 상태입니다.

## Firebase 설정 (구글 로그인 + 계정 데이터)

1. https://console.firebase.google.com 에서 새 프로젝트를 만듭니다.
2. 왼쪽 메뉴 **Authentication → 시작하기 → 로그인 방법**에서 '구글'을 사용 설정합니다.
3. 왼쪽 메뉴 **Firestore Database → 데이터베이스 만들기**로 Firestore를 켭니다. (테스트 모드로 시작해도 되지만, 이후 **규칙(Rules)** 탭에 이 프로젝트의 `firestore.rules` 내용을 붙여넣어서 본인 계정만 자기 데이터를 읽고 쓸 수 있게 해주세요.)
4. **프로젝트 설정(톱니바퀴) → 일반 → 내 앱**에서 '웹 앱 추가'를 누르면 `apiKey`, `authDomain` 등 설정값이 나옵니다. 이 값들을 `frontend/.env.example`을 복사한 `.env` 파일에 채워 넣으세요 (로컬 개발용).
5. Render에 배포할 때는 프론트엔드 서비스의 환경변수(Environment)에도 같은 값들을 등록해야 합니다. `render.yaml`에 `sync: false`로 표시해뒀는데, 이건 "Render가 자동으로 값을 만들지 않고 사람이 직접 입력해야 하는 값"이라는 뜻이에요. Blueprint를 처음 적용(Apply)할 때 Render가 값을 입력하라고 물어봅니다.

## 로컬 실행 방법

터미널 두 개를 열어서 각각 실행하세요.

### 1. 백엔드 (전투 로직 API)

```
cd backend
npm install
npm run dev
```

`http://localhost:3001` 에서 API 서버가 뜹니다.

### 2. 프론트엔드 (웹 화면)

```
cd frontend
npm install
npm run dev
```

터미널에 뜨는 주소(보통 `http://localhost:5173`)로 접속하면 됩니다. Vite 개발 서버가 `/api` 요청을 자동으로 백엔드(3001번 포트)로 전달하도록 설정해뒀습니다.

## Render 배포 방법 (베타 테스트용)

1. 이 폴더 전체를 GitHub 저장소에 올립니다 (`git init` → `git add .` → `git commit` → GitHub에 새 저장소 만들고 push).
2. Render 대시보드에서 **New → Blueprint**를 선택하고, 방금 만든 GitHub 저장소를 연결합니다. 루트에 있는 `render.yaml`을 Render가 자동으로 인식해서 백엔드(웹 서비스)와 프론트엔드(정적 사이트) 두 개를 한 번에 만들어줍니다.
3. 배포가 끝나면 백엔드 서비스의 실제 URL(예: `https://tower-of-flame-backend.onrender.com`)을 확인하세요. `render.yaml`에 적어둔 값과 실제로 배정된 주소가 다르면, 프론트엔드 서비스의 환경변수 `VITE_API_URL`을 Render 대시보드에서 실제 주소로 수정하고 프론트엔드를 다시 배포(Manual Deploy)하세요.
4. 프론트엔드 서비스의 URL이 실제 게임 주소입니다. 이 주소를 베타 테스터에게 공유하면 됩니다.

무료 플랜(Free)은 일정 시간 요청이 없으면 서버가 슬립 모드로 들어가서 첫 요청 응답이 느릴 수 있어요. 베타 테스트 인원이 늘어나면 유료 플랜 고려하세요.

## 아직 안 된 것 / 다음 단계

- 구글 로그인은 버튼만 있고 실제 Firebase 연동은 안 돼 있음 (버튼 누르면 바로 캐릭터 선택으로 넘어감) → 지금은 세션이 브라우저를 새로고침하면 사라짐
- 데이터가 서버 메모리에만 저장됨 (서버 재시작하면 모든 유저 데이터 초기화) → Firestore로 교체 필요
- 2~5구간 몬스터는 데이터에는 있지만 실제로 만나려면 20층 단위로 올라가야 확인 가능
- 레벨업, 인벤토리, 대장간, 상점, 수식어 시스템은 아직 미구현
- combat.js 안의 CONFIG 값 중 일부(크리티컬 확률 공식, 방어 배율, 마력 회복 비율)는 대화에서 정확히 정해지지 않아 추정치로 넣어둔 값입니다. 주석에 [추정]이라고 표시해뒀어요.
